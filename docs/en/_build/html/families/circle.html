Circle Graph

A circle graph is the intersection graph of a set of chords of a circle. Two vertices are adjacent if and only if their corresponding chords intersect.

See ISGCI entry for this class for the definition, inclusions, and complexity of graph problems.

Recognition

CircleAlgorithm

Description

NAJI_SYSTEM (default)

Naji’s characterization: the graph is a circle graph iff a certain system of linear equations over GF(2) (one variable per ordered pair of distinct vertices) is solvable. Solvability is decided by bitset Gaussian elimination in polynomial time. Decision only; no chord diagram is produced. The implementation first contracts twin classes to shrink the input, and enforces a memory limit on its dense GF(2) basis (throws std::runtime_error when exceeded). (Naji 1985; Gasse, Discrete Math. 173, 1997; Geelen–Lee, J. Graph Theory 93, 2020)

DOW_BACKTRACKING

DOW (double occurrence word) chord-diagram backtracking. Attempts to construct a chord diagram consistent with the input graph by placing chord endpoints on a circle. Produces an explicit DOW certificate on YES, but takes exponential time in the worst case (practical up to roughly n = 9; NO answers are the expensive side). The search runs under a step budget and throws std::runtime_error when it is exhausted instead of running forever.

inline CircleLabeledEnumerationResult graph_recognition::enumerate_circle_labeled_graphs_reverse_search(int n, CircleLabeledEnumAlgorithm algo = CircleLabeledEnumAlgorithm::REVERSE_SEARCH)

Enumerates all labeled circle graphs on vertex set {1, …, n}.

Parameters:

  • n – Number of vertices

  • algo – Algorithm selection (currently only REVERSE_SEARCH)

Returns:

CircleLabeledEnumerationResult

The enumerator above emits labeled graphs. A second one emits a single representative per isomorphism class, by McKay’s canonical construction path method – canonical deletion, the scheme Johnston (2020) applies to permutation and circle graphs (computing the circle counts up to n = 13). Graphs are grown one vertex at a time, which is sound because circle graphs are hereditary. No cheap incremental test decides whether adding a vertex keeps the graph in the class, so, as in the permutation enumerator, the pruning is a recognizer call (the polynomial-time Naji system) on every candidate child; it runs before the isomorph rejection, so the more expensive canonicalization only ever sees circle graphs. A child then survives only when the added vertex lies in the automorphism orbit of the canonically last vertex of the child. The counts are OEIS A156809(n) (1, 2, 4, 11, 34, 154, 978, 9497, 127954, …; every graph on at most 5 vertices is a circle graph), or the connected ones among them (A156808: 1, 1, 2, 6, 21, 110, 789, 8336, …) with connected_only set.

inline CircleUnlabeledEnumerationResult graph_recognition::enumerate_circle_unlabeled_graphs(int n, bool connected_only = false, CircleUnlabeledEnumAlgorithm algo = CircleUnlabeledEnumAlgorithm::CANONICAL_AUGMENTATION)

Enumerates all non-isomorphic circle graphs on n vertices.

Emits one representative per isomorphism class: A156809(n) graphs (1, 2, 4, 11, 34, 154, 978, 9497, … for n = 1, 2, …), or the connected ones among them (1, 1, 2, 6, 21, 110, 789, 8336, …) with connected_only. n = 0 yields the single empty graph in both modes; negative n and n >= 64 yield nothing.

Note

Every candidate child costs one circle recognition (Naji’s GF(2) system) plus, when it is a circle graph, one exact canonicalization (branch and bound over vertex orderings, worst case k! on vertex-transitive graphs), so the enumeration is practical to about n = 9 (n = 8 takes about 2 seconds, n = 9 about 50 seconds; A156809(9) = 127954).

Parameters:

  • n – Number of vertices (must be < 64; see the note on practical range)

  • connected_only – If true, emit only connected graphs

  • algo – Algorithm to use (default: CANONICAL_AUGMENTATION)

Returns:

CircleUnlabeledEnumerationResult

OEIS Count Check

The non-isomorphic enumeration was verified through n = 9 against OEIS A156809 (1, 2, 4, 11, 34, 154, 978, 9497, 127954), independently of the enumerator itself: the same counts come out of generating all unlabeled graphs on n vertices and filtering them by check_circle. With connected_only the counts match OEIS A156808 (1, 1, 2, 6, 21, 110, 789, 8336). The static test cases stop at n = 7.

Examples

Recognition example

#include <iostream>
#include "graph.h"
#include "circle.h"

int main() {
    using namespace graph_recognition;

    Graph g(4, {{1, 2}, {2, 3}, {3, 4}});
    auto result = check_circle(g);

    std::cout << std::boolalpha << result.is_circle << '\n';
    return 0;
}

Enumeration example

#include <iostream>
#include "circle_labeled_enum.h"

int main() {
    using namespace graph_recognition;

    auto result = enumerate_circle_labeled_graphs_reverse_search(4);
    std::cout << result.graphs.size() << '\n';
    return 0;
}

Non-isomorphic enumeration example

#include <iostream>
#include "circle_unlabeled_enum.h"

int main() {
    using namespace graph_recognition;

    auto result = enumerate_circle_unlabeled_graphs(6);
    std::cout << result.graphs.size() << '\n';  // 154 = A156809(6)
    return 0;
}
