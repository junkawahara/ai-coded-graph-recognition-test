Cograph

A graph is a cograph if it contains no induced P4 (path on 4 vertices).

See ISGCI entry for this class for the definition, inclusions, and complexity of graph problems.

Recognition

CographAlgorithm

Description

COTREE

Cotree construction via recursive connected-component / co-component decomposition.

PARTITION_REFINEMENT (default)

Same decomposition with a fast linked-list co-component search. Complexity: worst case O(n (n + m)) (each decomposition level rescans the adjacency lists).

MODULAR

Builds the modular decomposition tree and checks it has no PRIME node (see modular_decomposition.h in Utilities). A cograph’s modular decomposition is exactly its cotree, so this reaches the same structure by entirely different machinery – a useful independent cross-check, but slower at O(n^4).

inline CographResult graph_recognition::check_cograph(const Graph &g, CographAlgorithm algo = CographAlgorithm::PARTITION_REFINEMENT)

Determines whether a graph is a cograph.

A graph is a cograph if every induced subgraph on 2 or more vertices is disconnected or has a disconnected complement. Determined by recursively decomposing into connected components / complement connected components.

Parameters:

  • g – Input graph

  • algo – Algorithm selector (COTREE or PARTITION_REFINEMENT)

Returns:

CographResult

Cotree construction

The decomposition the recognition algorithms perform already is the cotree. build_cotree() keeps it instead of discarding it, returning it as an MDTree (see Utilities): a union step becomes a PARALLEL node, a join step a SERIES node, and no PRIME node ever appears. check_cograph() does not build the tree, so recognition costs the same as before.

inline CotreeResult graph_recognition::build_cotree(const Graph &g, CographAlgorithm algo = CographAlgorithm::PARTITION_REFINEMENT)

Builds the cotree of a graph.

The decomposition both recognition algorithms perform already is the cotree; this entry point keeps it instead of discarding it. On a graph that is not a cograph the decomposition gets stuck at an induced P4 and no tree is returned.

check_cograph() does not build the tree, so recognizing a cograph costs the same as before.

Parameters:

  • g – Input graph

  • algo – Algorithm to use (default: PARTITION_REFINEMENT)

Returns:

CotreeResult

inline CographLabeledEnumerationResult graph_recognition::enumerate_cograph_labeled_graphs_cotree(int n, CographLabeledEnumAlgorithm algo = CographLabeledEnumAlgorithm::COTREE)

Enumerates all labeled cographs on vertex set {1, …, n}.

Direct enumeration by recursive cotree construction. For n >= 2, the results of root type 0 (union) and 1 (join) are combined.

Parameters:

  • n – Number of vertices

  • algo – Algorithm selection (currently only COTREE)

Returns:

CographLabeledEnumerationResult

The enumerator above emits labeled graphs. A second one emits a single representative per isomorphism class by recursive cotree construction through the complement duality: for n >= 2 complementation swaps the cotree’s root type, so the connected cographs are exactly the complements of the disconnected ones, which in turn are composed of smaller connected cographs over integer partitions. No isomorph rejection is needed. The counts are OEIS A000084(n) (1, 2, 4, 10, 24, 66, 180, 522, …), or A000669(n) (1, 1, 2, 5, 12, 33, 90, 261, …) with connected_only set.

inline CographUnlabeledEnumerationResult graph_recognition::enumerate_cograph_unlabeled_graphs(int n, bool connected_only = false, CographUnlabeledEnumAlgorithm algo = CographUnlabeledEnumAlgorithm::COTREE)

Enumerates all non-isomorphic cographs on n vertices.

Emits one representative per isomorphism class: A000084(n) graphs (1, 2, 4, 10, 24, 66, 180, 522, … for n = 1, 2, …), or A000669(n) graphs (1, 1, 2, 5, 12, 33, 90, 261, …) when connected_only is set; the connected graphs come first in the output. n = 0 yields the single empty graph in both modes; negative n yields nothing.

Note

The result materializes every graph; the counts grow exponentially (A000084 passes one million around n = 17).

Parameters:

  • n – Number of vertices

  • connected_only – If true, emit only connected graphs

  • algo – Algorithm to use (default: COTREE)

Returns:

CographUnlabeledEnumerationResult

OEIS Count Check

For n = 2, 3, 4, 5, 6, the number of enumerated labeled cographs was verified to match the same integer sequence recorded as OEIS A006351: 2, 8, 52, 472, 5504. The non-isomorphic enumeration was verified through n = 10 against OEIS A000084 (1, 2, 4, 10, 24, 66, 180, 522, 1532, 4624), and against OEIS A000669 (1, 1, 2, 5, 12, 33, 90, 261, 766, 2312) with connected_only set.

Examples

Recognition example

#include <iostream>
#include "graph.h"
#include "cograph.h"

int main() {
    using namespace graph_recognition;

    Graph g(4, {{1, 2}, {1, 3}, {1, 4}, {2, 3}, {2, 4}, {3, 4}});
    auto result = check_cograph(g);

    std::cout << std::boolalpha << result.is_cograph << '\n';
    return 0;
}

Enumeration example

#include <iostream>
#include "cograph_labeled_enum.h"

int main() {
    using namespace graph_recognition;

    auto result = enumerate_cograph_labeled_graphs_cotree(4);
    std::cout << result.graphs.size() << '\n';
    return 0;
}
